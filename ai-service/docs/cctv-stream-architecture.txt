ICT LIBRARY OFFICE
CCTV STREAMING AND AI PROCESSING ARCHITECTURE

==================================================
SYSTEM OVERVIEW
==================================================

The ICT LIBRARY OFFICE CCTV system uses a centralized
MediaMTX server as the single streaming hub for all
video consumers.

The architecture is designed to support:

 ├── Real-time CCTV monitoring
 ├── Person detection
 ├── Face detection
 ├── Future face blurring
 ├── Future privacy protection modules
 ├── Web live view
 ├── Mobile live view
 └── Scalable AI integration

A single CCTV stream enters the system and is
processed only once before distribution to all users.



==================================================
PROBLEM IDENTIFIED
==================================================

The original implementation allowed multiple services
to consume the same RTSP stream independently.

Several components were opening their own RTSP
connections and performing their own decoding.

As the number of consumers increased:

 ├── CPU usage increased
 ├── Memory usage increased
 ├── H264 decoding errors appeared
 ├── Mosaic artifacts appeared
 ├── Frame corruption appeared
 ├── Stream latency increased
 └── MediaMTX stability decreased

==================================================
SINGLE SOURCE OF TRUTH
==================================================

Only one component is allowed to consume the original
RTSP stream directly.

That component is:

    Capture Worker

All AI modules operate on shared memory frames.

No AI module opens additional RTSP connections.

This eliminates:

 ├── Duplicate decoding
 ├── Stream contention
 ├── Reader conflicts
 ├── Frame backlog
 └── Unnecessary CPU usage



==================================================
COMPONENT RESPONSIBILITIES
==================================================

CAPTURE WORKER

 ├── Sole RTSP consumer
 ├── Connects to MediaMTX (/cctv)
 ├── Receives CCTV frames
 ├── Handles reconnects
 ├── Rotates frames when required
 └── Updates latest_frame


AI PROCESSING LAYER

 ├── Reads latest_frame
 ├── Performs person detection
 ├── Performs face detection
 ├── Future face blur generation
 ├── Future privacy filtering
 └── Produces processed frames


RTSP PUBLISHER

 ├── Receives processed frames
 ├── Encodes H264 stream
 ├── Publishes RTSP stream
 ├── Creates /processed stream
 └── Sends processed output to MediaMTX


MEDIAMTX

 ├── Hosts /cctv stream
 ├── Hosts /processed stream
 ├── Central streaming hub
 ├── Supports multiple readers
 └── Eliminates direct consumer conflicts


BACKEND FFMPEG HLS

 ├── Reads only /processed stream
 ├── Converts RTSP to HLS
 ├── Generates .m3u8 playlists
 ├── Generates .ts segments
 └── Serves live streams


WEB AND MOBILE CLIENTS

 ├── Consume HLS stream
 ├── Receive processed video
 ├── Receive AI overlays
 └── Future face-blurred stream

==================================================
DESIGN OBJECTIVE
==================================================

Provide a scalable, privacy-aware, AI-assisted CCTV
architecture that maintains a single authoritative
video source while supporting future computer vision
modules such as person detection, face detection,
head detection, automatic face blurring, automatic
head blurring, tracking, analytics, and privacy
protection features.
